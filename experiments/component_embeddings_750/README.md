# Эмбеддинги компонентов: 750 ответов

Новый опыт с MLP/FFN: `run_mlp_experiment.ipynb`, 31 метод, только готовый кэш.
Архитектуры и протокол описаны в `MLP_DESIGN.md`.

Запуск: `run_experiment.ipynb`, T4 GPU, «Выполнить все».
Готовые пользовательские эмбеддинги теперь сохранены в `embedding_cache/`:
пять частей до 48 МиБ, восстановление и контроль SHA256 автоматические.
Повторное получение векторов и загрузка весов не выполняются; достаточно CPU.
Точные тексты, модель и подпись набора проверены; векторы не перекодировались.
Папка самодостаточна: входы в `data/`, код, модель, оценка и отчёт.

## Данные

750 исходных ответов Llama; 494 без галлюцинаций, 256 с галлюцинациями.
Метки GPT-4o, не ручная разметка. 6950 сущностей, 5927 отношений, 3991 утверждение.
В архиве ec750 уже есть прежние 100 ответов; они не добавляются повторно.
Используются только исходные ответы, исправленные варианты исключены.

Контрольные суммы текстовых входов считаются после замены CRLF на LF;
переносы Windows/Linux не меняют идентичность набора. Git закрепляет LF для
данных. Изменения содержимого по-прежнему вызывают ошибку загрузки.

Подтверждённость определена для сущностей и утверждений. Для отношений есть
извлечение троек, но нет проверки. Они помечены `not_verified`; вместо
прежних 13 используются 9 доступных признаков, перечисленных в `data_io.py`.
Статусы отношений не подменяются выводом о поддержке или противоречии.

## Модель и тексты

Qwen/Qwen3-Embedding-8B, версия `1d8ad4ca9b3dd8059ad90a75d4983776a23d44af`,
4096 координат, 8-битное хранение весов через bitsandbytes, вычисления FP16.
Это более крупная модель, чем использованные ранее 4B/GTE. Квантование может
немного изменить векторы; формат записывается в манифест. Реальный расход
памяти измеряется в Colab, пакет автоматически выбирается с запасом 10%.
FP16-версия 8B целиком не помещается в обычную T4. Улучшение результата этой
задачи по размеру модели не гарантируется.

Сущность — ответ и целевая сущность; отношение — ответ и полная направленная
тройка; утверждение — отдельный текст; общий вектор — ответ. Опорный контекст
не добавляется. Используется последний токен и нормирование длины вектора.
Изолированные варианты троек, GTE и тяжёлые сети больше не запускаются.

## Оценка

- 629 ответов для разработки: групповая кросс-валидация 5 частей × 3 повтора.
- 121 ответ для отложенной проверки, без групп из прежней сотни.
- Одинаковые входы и копии ответов объединены: 693 группы, граница не пересекается.
- Классы не балансируются искусственно.
- Главная пара: Q|logreg против Q_MEAN|logreg.
- 9 признаков + 24 координаты средних E/R/C после PCA = 33 признака.
- PCA обучается на средних векторах только обучающих ответов; регуляризация
  логистической регрессии выбирается во внутренних 3 групповых частях.
- Другие модели имеют фиксированные параметры до нового запуска.
- В контрольной строке Q_SHUFFLED семантическая часть переставляется отдельно
  внутри обучения и проверки; усредняются 5 перестановок. Это диагностический
  контроль с дополнительным усреднением, не симметричный тест значимости.

32 метода — 23% прежних 139. Семь представлений × четыре модели дают 28 строк;
ещё четыре — векторы без подтверждённости, перестановочный контроль, частота
класса и доля неподтверждённых сущностей. Последняя не является полной HalluGraph:
для её воспроизведения не хватает исходных проверок отношений.

Метрики: ROC-AUC, PR-AUC (средняя точность), логарифмическая ошибка, F1 при
пороге 0.5. Сохраняются среднее и стандартное отклонение по 15 частям и
среднее/стандартное отклонение итоговых метрик между 3 повторами. Стандартное
отклонение — разброс, не доверительный интервал. Для главной разницы на
отложенной части строится 95% интервал через пересэмплирование целых групп.
Выбор нового победителя по отложенной таблице потребует независимой проверки.
Новые оценки E/C получены другим протоколом; сравнение с прошлой сотней
одновременно меняет размер выборки и извлечение компонентов.

## Файлы

- `prepare_data.py` — воспроизводимая сборка из пользовательского архива.
- `data_io.py` — чтение и проверка данных.
- `embeddings.py` — закреплённая модель, тексты, память и кэш.
- `compact_experiment.py` — все признаки, модели и разбиения.
- `report.py` — проверка метрик и полный архив.
- `smoke_test.py` — ограниченная локальная проверка.
- `build_notebook.py` — сборка ноутбука.

## После запуска

Ноутбук скачает `component_750_results.zip`. При блокировке браузером файл
можно скачать через панель файлов Colab. Пришлите весь ZIP: в нём прогнозы,
метрики с разбросом, отложенные сравнения, векторы, точные тексты, данные,
код, HTML/Markdown-отчёт и контрольные суммы.

Сборка данных вручную (в Colab это уже не требуется):

```bash
python prepare_data.py ec750-complete-20261003.tar.gz --pilot-labels ../component_embeddings_colab/data/labels.csv
```

Локальные проверки не загружают большую модель и не запускают полный опыт.

Источники модели: https://huggingface.co/Qwen/Qwen3-Embedding-8B
и https://arxiv.org/abs/2506.05176.
