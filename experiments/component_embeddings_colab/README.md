# Опыт 2: векторы компонентов в Google Colab

Основная точка запуска — `run_grid_experiment.ipynb`. Папка содержит данные,
код двух замороженных кодировщиков, признаки, модели, оценку и формирование
полного архива. Полный опыт выполняется в Colab; локальные проверки не
скачивают веса и не обучают всю сетку.

## Зачем изменена методика

Предыдущий проверенный запуск GTE-large содержал 139 методов. Лучший результат
дал градиентный бустинг только на 13 признаках подтверждённости: ROC-AUC
`0.7122`. Лучший вариант с PCA-средними GTE-векторов дал `0.6864`. Для
логистической регрессии добавление PCA-средних снизило ROC-AUC с `0.6696` до
`0.6488`; сырые средние снизили его на `0.1832`.

Выбор максимума из 139 строк на той же сотне ответов не является чистой
проверкой гипотезы. Поэтому новая версия разделяет результаты:

1. Основная проверка — одинаковая логистическая модель на 13 признаках против
   тех же 13 признаков с Qwen3-векторами. Регуляризация выбирается внутренним
   разделением, PCA обучается только на обучающих ответах.
2. Сравнение кодировщиков — Qwen3 и GTE-large получают одинаковые тексты.
3. Отрицательный контроль — Qwen3-векторы переставляются между ответами при
   сохранении размерности признаков и классификатора.
4. Разбор типов — сущности, отношения и утверждения добавляются отдельно.
5. Матрица 139 сочетаний остаётся разведочным поиском идей.

## Кодировщики

Основной: `Qwen/Qwen3-Embedding-4B`, ревизия
`5cf2132abc99cad020ac570b19d031efec650f2b`. Модель содержит 4,02 млрд
параметров, использует 2560 координат и поддерживает инструкции. Файлы весов
занимают около 8,06 ГБ. В T4-машине Colab веса переводятся в FP16, используется
стандартное экономное внимание PyTorch и автоматически выбирается пакет на
самых длинных входах с пределом 90% видеопамяти.

Контрольный: `Alibaba-NLP/gte-large-en-v1.5`, ревизия
`104333d6af6f97649377c2afbde10a7704870c7b`, 1024 координаты.

Обе модели заморожены. Целевые метки не участвуют в получении векторов.
Модели запускаются последовательно и выгружаются из видеопамяти между
проходами.

## Формирование текстов

- Сущность: полный ответ и явно указанная целевая сущность.
- Отношение: полный ответ и полная направленная тройка с отдельными субъектом,
  предикатом и объектом.
- Утверждение: его текст отдельно.
- Изолированный вариант: только сущность, полная тройка или утверждение.
- Общий вектор: полный ответ.

Опорные документы не подаются кодировщикам. Они уже используются при расчёте
подтверждённости; их добавление смешало бы две проверяемые группы признаков.
Qwen3 объединяет текст по последнему токену, GTE-large — по первому служебному
токену. Усечение запрещено, все результаты нормируются по длине.

## Данные

В `data/` находятся 100 ответов, 2385 компонентов, 13 признаков
подтверждённости, пять зафиксированных частей, HalluGraph и отдельные целевые
метки GPT-4o. Выборка искусственно сбалансирована 50/50 и не является
независимым ручным эталоном.

## Запуск

Откройте `run_grid_experiment.ipynb` через GitHub в Colab, выберите T4 GPU и
нажмите «Среда выполнения → Выполнить все». Ноутбук сам:

1. установит зависимости и проверит данные;
2. рассчитает GTE-large и Qwen3-Embedding-4B;
3. проверит размерности и один шаг каждой группы моделей;
4. выполнит основную проверку и сравнение кодировщиков;
5. рассчитает разведочную матрицу;
6. пересчитает метрики из отдельных прогнозов;
7. создаст русский отчёт и автоматически скачает
   `component_qwen3_4b_results.zip`.

Если браузер заблокирует автоматическое скачивание, ссылка на архив останется
в последней ячейке. Для следующего аудита нужен только этот ZIP. В нём будут
оба набора векторов, журналы текстов, все прогнозы, метрики по частям, основная
и разведочная таблицы, входные данные, HTML/Markdown-отчёты и контрольные суммы.

## Ограничение вывода

Новая версия лучше отделяет эффект векторов от эффекта классификатора, но
размер выборки остаётся равным 100. Даже положительный результат основной
строки следует подтвердить на новых ответах с заранее замороженной
конфигурацией и независимой разметкой.
